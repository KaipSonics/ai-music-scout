# API-сервер для браузера и CORS

Node.js 24, без дополнительных npm-зависимостей. Код — `server/app.mjs`. Он обслуживает `dist/` и `/api/vk/<method>`; production сборка Pages может обращаться к отдельно размещённому HTTPS API.

## Конфигурация

Переменные окружения задаются на сервере, не в Vite и не в Git:

- `SCOUT_ACCESS_KEY`: случайный секрет не короче 24 символов. Создайте через `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` и сохраните в секретах хостинга. Не отправляйте его в issues/чаты.
- `SCOUT_ALLOWED_ORIGINS`: точные origin через запятую, например `https://kaipsonics.github.io,https://scout.example.com`. Без wildcard. Укажите origin даже для same-origin размещения.
- `PORT`: по умолчанию 8787.
- `HOST`: по умолчанию 127.0.0.1. На управляемом хостинге за его HTTPS reverse proxy может потребоваться 0.0.0.0.

```sh
npm ci
npm run build
npm run start:server
```

Запускайте через HTTPS reverse proxy с корректными TLS-сертификатами. В интерфейсе Настройки → API-сервер для веба введите HTTPS-адрес и ключ доступа. HTTP допускается только для localhost-разработки. В browser build эти значения не вшиты. Поле ключа замаскировано, значение не сохраняется после reload. VK-токен отправляется только выбранному доверенному серверу и VK на время запроса. Сервер не хранит токены и не ведёт журнал тел запросов.

GitHub Pages не исполняет серверный код. Без отдельно настроенного сервера веб может работать через прямой VK fetch только если VK разрешает CORS; иначе оператор увидит явную диагностику. Tauri использует нативный транспорт без этого backend.

## Границы доступа

Разрешены только users.get, groups.getById, groups.search, newsfeed.search, wall.get, с фиксированным VK HTTPS endpoint, ограниченными параметрами и без redirect. Нет произвольного proxy URL и messages.send. API требует Bearer-ключ сервера и точный разрешённый Origin. Сам ключ общий для небольшой доверенной команды; это не система персональных аккаунтов или публичный SaaS.

Размер тела ≤16 KiB, счётчик ≤100, запрос к VK ограничен 18 секундами, повторные запросы одного токена ограничены по времени (400 мс на клиенте, минимум 370 мс на сервере). В памяти сервера остаётся только короткоживущий SHA-256 fingerprint для ограничения частоты, не сырой токен. Ошибки VK возвращают код без произвольных provider/request деталей. Ответы имеют no-store и nosniff.

Конфигурация происхождения запроса, ограничения и авторизация тестируются реальными HTTP-запросами к локальному серверу, upstream VK в этих тестах — явные фикстуры. Развёрнутого production сервера и авторизованного живого VK-теста в этой работе нет.
